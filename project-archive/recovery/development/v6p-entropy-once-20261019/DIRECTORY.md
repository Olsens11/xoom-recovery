## Problem and reproduced cause

With all eight Toolkit Auto Load settings disabled and saved, v6O cold-booted with every package UNLOADED. Wi-Fi Runtime was manually Loaded/Started; Desktop Commander could only be Loaded after Wi-Fi was ready because of an **independent incorrect Load-time Wi-Fi gate**. Desktop Commander Start then correctly auto-loaded and ran missing Time Sync, reached SYNCED, and reported Desktop Commander RUNNING. However the agent did not request a fresh cloud pairing code.

Three Node 24 JavaScript processes—including a minimal `node -p process.version`—hung before initializing, whereas `node --version` worked; each blocked process held `/dev/random` open. Kernel entropy was 42 bits, below a 64-bit wake threshold. Independently generated cryptographic randomness credited to the kernel using `RNDADDENTROPY` unblocked all three processes; the foreground agent connected to the provider, obtained a short-lived device code, and published its temporary QR and PENDING state. The expired code/token are **not recorded**. This establishes an actual cold-boot entropy blocker; it does not imply the SSH server produced it.

## Selection and design

Use vetted upstream [jitterentropy-library](https://github.com/smuellerDD/jitterentropy-library) **v3.6.3**, commit `c90ff465dcdb6a6949542c72a26a8ab496daa8cb` (dual BSD/GPL; retain original LICENSE files), not a custom cryptographic noise estimator. `jent_entropy_init_ex(2, JENT_FORCE_FIPS)` and continuous health tests must pass before crediting an intentionally conservative 128 estimated bits from 64 generated bytes. `--probe` tests the library without changing the kernel RNG. `--ensure` skips immediately if available entropy is already >=128 bits; otherwise collects, uses `RNDADDENTROPY`, wipes its output buffer, and exits. A 35-second alarm bounds startup. No static predictable seed, writable SD entropy cache, persistent entropy daemon, package modification, or privileged cloud change.

The recovery init `on boot` action starts the disabled/explicit one-shot `xoomentropyonce` service; the centrally owned Desktop Commander Start entry point invokes `/sbin/xoom_entropy_once --ensure` before launching Node, failing closed if the helper fails. **Package Load remains independent of this new readiness check**; the pre-existing Wi-Fi Load gate is still a separate open defect.
