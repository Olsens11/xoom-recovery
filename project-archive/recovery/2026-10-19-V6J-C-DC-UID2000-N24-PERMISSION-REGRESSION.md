# 2026-10-19 — Desktop Commander worker regression traced to n24 directory permissions

**Physical diagnosis, no runtime fix applied:** Xoom v6J-C remains booted. Desktop Commander 0.16.3 has first-party QR authorization and Supabase Realtime SUBSCRIBED/Online using the proven split-mode JITless QR child, but its restricted UID2000 worker fails with `Cannot load externalized builtin: "internal/deps/undici/undici:/tmp/n24/undici-fetch.js"`. Root cause traced to `0700 root:root` directory permissions on `/tmp/n24`, mismatched with UID2000 worker execution. **Root UID0 isolated Node starts, UID2000 Node aborts with the exact same externalized-builtin failure. A mode/owner correction has NOT YET been applied or end-to-end tested.**

## Historical working reference and exact source comparison

- [October 18 v6G original v0.16.0 physical QA](2026-10-18-V6G-PHYSICAL-TOOLKIT-QA-CHECKPOINT.md) documents **actual ChatGPT remote read/list/write/readback and SHA operations** through the Xoom filesystem worker, with files owner UID/GID 2000 and mode 0600. That earlier PASS required manually staging externalized Node builtin dependencies and holding a foreground ADB agent session; it was not a fresh-boot production init-managed PASS.
- [Original v0.16.2 automatic builtin restoration](../packages/desktop-commander/2026-10-18-DC-0162-PINNED-NODE-BUILTINS-AB-QA.md) was intentionally a targeted fix for missing Node builtins, not a worker privilege change. v0.16.2 added `restore_node_builtins()` to `control.sh`, and v0.16.3 carried it unchanged. Verified current `control.sh` SHA `5b43f185c54542e15d034ff833a998463a419714ebebdf767da1433bd1440202`; current `agent-remote-offline-poc.mjs` SHA `308a3a5e18f8c7b4fba0154e7459b01517c482c4cf05c1b8a3083c91b46df471`; restricted `xoom-scratch-fs-worker-v13.js` SHA `90acbe94a2d1a840457d83526c7e26c92579a73a1e4dd935b3537bcff1bf8562`. This is not evidence those files have ever changed since their earlier working versions; the worker implementation itself did not need alteration for this regression.
- The original frozen Node archive (`n24-externalized-builtins-20261018.tar.gz`, 232,932 bytes SHA `0d3e2918d1774c0762e800ce95d510a444bb8fcda95b3a50a32dc6db132fba91`) has only **three regular-file tar entries** `n24/undici-fetch.js`, `n24/acorn.js`, `n24/walk.js` with mode `0644`, and **no explicit n24 directory entry**. The `control.sh` begins with `umask 077`, then does `busybox tar -xzf "$N24_ARCHIVE" -C /tmp` when `/tmp/n24` is absent. This combination can create `/tmp/n24` as `0700` under root. The routine checks symlink avoidance, three present regular files and exact SHA, but does **not** establish directory accessibility for UID2000. It emits `NODE_BUILTINS_REUSED_AND_VERIFIED` even though the restricted worker cannot traverse that directory.

## Minimal proposed correction — NOT INSTALLED

After guarded checks that `/tmp/n24` is a genuine root-owned directory with the correct three SHA-pinned files, allow only the restricted `shell` group to traverse it, e.g. **root:shell mode 0750**, leaving the three 0644 files unchanged and permitting no writes by UID2000. This keeps `/tmp/n24` root-controlled and does not grant shell/root access to any new services. Verify UID2000 Node startup and an actual remote `read_file`/`get_file_info` through Desktop Commander **while preserving the live main agent/QR/realtime state**. If OS directory access alone does not resolve it, investigate Node `--permission` read allowlist separately; do not assume a full worker PASS yet.

For permanent packaging, update only the Desktop Commander-owned `restore_node_builtins()` logic to create/verify the correct root owner, `shell` group and safe mode **both on fresh extraction and on reuse**, without relaxing working filesystem tool policy or modifying the main agent. Produce a new immutable versioned ZIP with updated pins only after hardware testing. No recovery flash or original SD v0.16.3 replacement is authorized by this analysis.
