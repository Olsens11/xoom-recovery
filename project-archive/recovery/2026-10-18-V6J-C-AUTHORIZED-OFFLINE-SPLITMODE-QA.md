## Discriminating on-device transport tests (no user credentials)

- Separate Node test resolved the actual Supabase project hostname, established certificate-verified TLS 1.3 and received expected HTTP `401 Unauthorized` for a raw WebSocket upgrade **without** an API key. A second independent raw TLS upgrade using the *public publishable key* fetched ephemerally from the official `/api/mcp-info` gave **HTTP `101 Switching Protocols`**, 256 ms. No private session JWT was read, displayed or stored.
- Against the same public publishable-key Realtime endpoint with the same ARM/glibc Node 24 binary, standalone native `globalThis.WebSocket` under **`--jitless`** failed in **347 ms** with a generic WebSocket error (no server detail). Under **normal JIT**, native WebSocket opened in **1,155 ms** and its Phoenix heartbeat returned `ok` in **1,194 ms**. This reproduces why the authorized agent cannot reach online when its entire Node process is JIT-disabled. It is the intersection of two platform-specific failures: default JIT crashes QR generator, while `--jitless` breaks Node's built-in WebSocket client. No network policy modification is justified.
- A **split-mode** isolated QA harness, run under *normal* Node, used `spawnSync()` of the same Node binary with **`--jitless` only in the QR worker**, used the real installed QR bridge with FAKE data and an isolated volatile output directory. Result: child exit 0 in **937 ms**, parent confirmed `state.txt` and `qr.pbm`, cleaned up. It did not interact with the provider or production QR state.
- The concrete candidate wrapper and child helper were then staged in an entirely separate RAM clone `/tmp/xoom-dc-splitmode-code-qa-20261019`, with the core bridge ROOT rewritten **only in the QA clone** to `/tmp/xoom-dc-splitmode-code-qa-state`. The normal-JIT parent invoked the exact proposed wrapper, which launched the QR helper in `--jitless` mode. **PASS:** QR side 45, `qr.pbm` 4,111 bytes, state file 38 bytes, **824 ms**, wrapper `clear('STOPPED')` removed QR, synthetic files cleaned. Never loaded a real verification code into that QA instance. This is a RAM-only functional prototype, not a released package or live paired connection.
